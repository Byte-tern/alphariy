# Альфа-Навигатор финансирования · учебное демо (Команда 44)
Next.js 14 + TypeScript. Данные вымышлены, оценки `source: mock`, реальной интеграции с банком нет.
Запуск: `npm install && npm run dev` · тесты: `npm test` · сборка: `npm run build`.
Деплой: импорт GitHub-репозитория в Vercel (Framework: Next.js, ключей не нужно) или `npx vercel --prod`.

## Вкладки
- **Решение оптимизатора** — конструктор профиля клиента (компания, пользователь, потребность, отрасль, структура, поведение) и пайплайн решения: новые признаки и ранг → бизнес-правила → адресат и действие; ниже «Было / Стало»: баннер для всех против персональной карточки с отраслевой визуализацией, таймлайном каналов и лимитами.
- **Путь клиента** — кликабельный экран интернет-банка: сравнение, запрос, передача расчёта уполномоченному, микро-сигналы сессии (возвраты назад, повторные сравнения, пауза, брошенный черновик → push), лог реакций.
- **Два клиента** — одна и та же ситуация у двух компаний даёт разный продукт, текст, адресата, канал и частоту.
- **Воронка модели** — синтетическая симуляция 10 000 компаний (`lib/funnel.ts`), до/после, топ-10 с вкладами признаков и таблица допущений. Допущения генератора не являются данными банка.
- **Сценарий демо** (кнопка в шапке) — пошаговый тур на 9 шагов, стрелки ← → и Esc.

## Устройство
- Логика решений — `lib/decision.ts` (чистая функция, одна и та же на клиенте и сервере). Пороги и ставки — `lib/config.ts` (демо-допущения).
- `POST /api/decision` — решение для профиля; `POST /api/requests` — отправка запроса: сервер заново проверяет право отправки, сумму/срок и применимость инструментов, номер запроса детерминирован (повтор даёт тот же номер).
- Роль и право отправки берутся только из профиля пользователя (`lib/ctx.ts`), переключатели панели их не выдают.
- Состояние (профиль, переопределения, сессия пути, запросы, передачи) хранится в localStorage браузера; API stateless.
